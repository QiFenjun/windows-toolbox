# Windows Toolbox v1.12.1 Validation

## Baseline and navigation diagnosis

- Baseline: v1.12.0, commit `257638706314e64727cd427c41f4124f9232647e`, 708 tests.
- The reported manual rapid-click white screen/unresponsive/crash symptom was **not reproduced** by the offscreen 100-request route run. Baseline instrumentation recorded 100 completed requests and no route failures, with a 562 ms maximum Dispatcher heartbeat gap. That first run also exposed a host-relative theme pack URI exception in the integration host; theme dictionaries now use an assembly-qualified component URI.
- Code-path audit found two concrete navigation-path costs: each tool route rebuilt all Home cards through `HomeViewModel.Refresh`, and `RememberRecent` started independent settings saves whose directory creation and destination truncation ran synchronously before asynchronous serialization. These paths are fixed: recent navigation updates only the recent list; settings snapshots are serialized away from the UI dispatcher, saves are serialized per service instance, and a temporary file is atomically moved into place.
- `NavigationService` gives each request a generation and checks it after factory execution and navigation callbacks. A stale factory result cannot replace the current page. Factories are synchronous; current module ViewModels do not asynchronously publish a navigation result. Cached ViewModels remain alive across view unloads, while view-level timers/event subscriptions keep their own Loaded/Unloaded lifecycle.
- The shell has no route transition animation to overlap. Sidebar animations replace prior animations, and delayed maximize/restore callbacks carry a transition generation. Navigation has no debounce, button lockout, global exception swallowing, or persistent navigation log.
- Application-level Dispatcher, unobserved-task, and AppDomain exception diagnostics report only the exception type and HRESULT through `Trace`; they do not mark unknown dispatcher exceptions handled.

## Localization and UX

- Supported UI languages: Simplified Chinese (`zh-CN`) and English (`en-US`); default is Simplified Chinese. Language is saved in `%AppData%\WindowsToolbox\settings.json`; old settings without the field migrate safely, and unknown values fall back to Chinese.
- Language selection is a two-item menu left of the theme control. The selected item is marked; changing language refreshes the Shell, sidebar, header, Home cards, cached Settings options/status, and current search results without restarting.
- Localized coverage: Shell/brand, Home, Settings, About, categories, top-level module names/descriptions, common tooltips/buttons, and Theme/Motion/Startup options. Deep module business pages still contain untranslated Chinese text and are not claimed as fully bilingual.
- Public navigation, Home cards, and page headers show one language at a time. ComboBox items use explicit `DisplayName` templates and `TextSearch.TextPath`, not object `ToString()`.
- Sidebar icons use a fixed 36-DIP column with the active marker overlaid, including the 72-DIP collapsed layout. Header spacing and language/theme alignment were checked in the offscreen Shell.

## Local integration checks

- `--navigation-stress`: PASS. 100/100 WPF Shell requests completed; 0 stale, cancelled, failed, or unhandled exceptions; 87 cache hits; final page `window-tools`; 50 requests with Full motion and 50 with motion Off; two theme changes during navigation; menu-driven Chinese-to-English switching and single-language Shell checks passed; Chinese and English Settings ComboBox templates passed; sidebar collapsed/expanded geometry passed. Longest Dispatcher heartbeat gap: 328 ms; slowest navigation plus layout: 73 ms. The harness uses safe probe ViewModels, an isolated settings file, and the actual WPF Shell/Dispatcher; it does not invoke tool side effects.
- `--ui-smoke zh-CN` and `--ui-smoke en-US`: PASS in both Light and Dark, covering all 11 module views and 8 Utilities pages at the smoke layout size.
- `--restart-manager`: PASS with real temporary Unicode locked/unlocked files, PID/start-time validation, multi-file and folder scans, and cancellation/error session cleanup. A 396-character path was explicitly reported as unsupported by the OS Restart Manager (error 29), not as a clean scan.
- `--keep-awake`: PASS; each native execution-state mode was immediately released.
- `--stress`: PASS; 20,000 temporary files, batch bounds, cancellation, junction handling, access-denied handling, ACL restoration, and cleanup.
- `--qr-roundtrip`, `--secure-rng`, `--screen-picker`, `--image-smoke`, and `--regex-smoke`: PASS. Screen sampling read only its synthetic test window; GDI count remained stable (22 before/after). One pre-fix full matrix run caught a first-paint race (black on the initial sample); the check now waits up to two seconds for the synthetic color before the strict 500-sample loop, and the final full matrix passed. The secure-random smoke is not a statistical security test.
- UI smoke writes images only under ignored `artifacts/ui-smoke`; no test output or fixture was committed.

## Security, privacy, and pending manual checks

- Navigation diagnostics contain only route IDs, stage, elapsed time, cache status, and exception type in process memory. No file paths, window titles, clipboard content, image paths, regex input, hashes, or generated values are logged.
- Unhandled exception diagnostics include only exception type and HRESULT; exceptions are not swallowed.
- No dependency was added. Language resources are embedded XAML dictionaries. Settings writes stay within the existing per-user settings path.
- Manual physical sidebar clicking, keyboard/accessibility review, and 125%/150% multi-monitor/mixed-DPI behavior remain **Pending**. Offscreen smoke is not represented as manual verification.
