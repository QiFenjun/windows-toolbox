## Architecture / Restart Manager

- `lock-inspector` / 占用检测 / Lock Inspector, Productivity Tools; `LockScanService`, `ScanFileEnumerator`, `ProcessDetailsService`, selected-process `ProcessIcon`, cached module ViewModel.
- `IRestartManagerClient` is the test boundary. Native declarations are centralized in `Interop/RestartManagerNative.cs`; structure sizes are tested (12-byte unique process, 668-byte process info).
- Only `RmStartSession`, `RmRegisterResources`, `RmGetList`, `RmEndSession`. RmShutdown: **NO**. RmRestart: **NO**. A successful Start owns a session; finally calls End on normal return, error, cancellation and exceptions. Failed Start does not close an unowned handle. End errors are reported.
- Register a resource batch once, probe GetList and retry ERROR_MORE_DATA at most three additional times, with a bounded buffer. Errors including access denied, invalid handle, memory, bad arguments, timeout, changing list and unsupported path have readable bilingual messages and numeric detail.
- Results retain application/service metadata, PID + full start FILETIME, RM type/status/session/restartable, optional current process name/path. Missing or protected-process metadata is nonfatal. Dedup is by process instance, with service/application identity fallback. Multi-file results are associations with the resource set, not fabricated per-file counts.
- Copy uses the retained metadata. Opening a program location rechecks PID + start time, checks path existence, then calls Explorer with ProcessStartInfo.ArgumentList; Task Manager is opened without simulated input. Shell icon extraction is limited to the selected executable, local and in memory. Existing providers have different module inputs/index extraction/caches, so existing modules were not refactored.

## Folder / Drive / limitations

- Stream `EnumerateFiles`/`EnumerateDirectories` using EnumerationOptions; no all-files array or preliminary full counting pass. 256-file batches each have their own RM session. Caps: current directory 5,000; recursive 20,000 files, 20,000 directories, depth 64. Memory is bounded by these caps.
- Skip reparse points, missing/inaccessible entries; continue sibling directories and preserve partial results. Cancellation stops further enumeration and closes the current RM session after the in-flight API returns. ViewModel serializes replacement scans and guards results/progress by generation.
- Ready local logical drives are shown using DriveInfo. Only DriveType.Removable is labelled removable; Fixed does not imply internal hardware. Drive scans use the same bounded enumeration. No eject is performed, including on empty results.
- Restart Manager is based on registered file resources. **Folder/drive modes cannot guarantee detection of directory-only, volume, device or driver handles.** No-blocker wording never promises a device can be removed safely. UNC single files can be attempted; network directory recursion is intentionally skipped.
- Native 396-character Unicode path observation on this machine: RmRegisterResources returned **29**, registered 0, blockers 0. This is reported as unavailable/possibly unsupported long path, **not** as a successful empty result. Long paths are queried separately; a locked normal file in the same request remains detectable. Paths are never truncated. Other Windows/path combinations may differ.

## Keep Awake

- `keep-awake` / 保持唤醒 / Keep Awake; `KeepAwakeService`, `IExecutionStatePlatform`, `WindowsExecutionStatePlatform`, module-owned ViewModel.
- Modes: System; SystemAndDisplay. Presets: 15/30/60/120/240 minutes and indefinite. Default System, 30 minutes. Active configuration is disabled; duplicate Start does not create an additional request.
- One stable background **MTA Thread per activation**, kept alive for the request. It calls SetThreadExecutionState once with `0x80000001`, or `0x80000003` for display. Its finally calls `0x80000000` on the same thread, then exits. Stop/Dispose join the owner; release failure is reported and thread exit provides the lifecycle fallback.
- States Inactive/Active/Stopping, mode and start/expected-expiry timestamps. Duration uses TimeProvider's Stopwatch-based monotonic timestamp, not wall-clock decrementing. The UI's one-second DispatcherTimer only updates display and stops on Unloaded; expiration runs independently of the UI.
- Closing an active window enters the existing tray. Hiding/navigating does not release. Stop, expiration and genuine App.OnExit release; tray Exit explicitly stops first. Restart begins Inactive even with startup registration.
- Only last selected mode/duration are persisted in existing settings. No active-state persistence or startup auto-awake. Invalid saved preferences fall back safely. Custom minutes, dynamic home status and battery-state detection are optional and omitted; UI gives a general battery-use note.
- **Power Plan Modified: NO. Registry Modified: NO. Mouse/Keyboard Simulation: NO. Startup Auto-Awake: NO. App Exit Releases Request: YES.** Manual sleep/hibernate/shutdown, locking/screensaver authentication, battery/critical power and administrator policies are not overridden.
- A zero API result is failure even if extended error is unavailable. Only operation and numeric error are traced. SetThreadExecutionState does not guarantee meaningful extended Win32 error information; zero is labelled unavailable, not a success indication.

## Safety / privacy / regression

For both **new modules**: Kill Process NO; Close Remote Handle NO; Elevation NO; Injection NO; Driver NO; Device Eject NO. No HTTP client, upload, registry change, power-plan change, shell command interpreter or simulated input. Lock Inspector does not read target contents, persist history/recent targets, or log filenames/paths/process lists. Only in-memory results and user-requested clipboard copies contain metadata.

Repository-wide search also found **pre-existing baseline exceptions**: NetworkTraffic's helper client uses `runas` for the explicit advanced-monitor request and `.Kill(entireProcessTree: true)` as a fallback to clean its own helper; InstalledApps can use `runas` for a user-requested uninstaller. Their business logic was not changed, neither new module references/reuses them, and this report does **not** claim those strings are absent from the entire repository. Other prohibited RM/system-handle/device-eject calls are absent from production source. Prohibition strings in tests/docs are expected.

All 315 previous regression tests remain passing for Shutdown Scheduler, App Manager, Network Traffic, Clipboard+, Text Tools, File Tools, Quick Launch and Window Tools. App changes are limited to module references/registration, data templates, Keep Awake tray/exit lifecycle and the generic tray tooltip; Core adds two preference fields.
