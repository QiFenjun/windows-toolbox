# Windows Toolbox v1.11.0 validation

## Baseline and scope

- Previous release: v1.10.0, commit `06c211b5b124d96d0562dabf41b71160f5639240`, 497 tests.
- Repository began clean on `main`; final implementation adds Unit Converter and Developer Tools inside existing Utilities (`utilities`). No new Sidebar module or dynamic tool/plugin loader was added.
- QR Tools, Color Tools, Time Tools and Random Tools business logic remains unchanged.

## Build and tests

- Release build: 0 warnings, 0 errors.
- Release tests: 646/646 passed (497 baseline + 149 new).
- New tests: `UnitConverterTests` (catalog, linear/temperature conversion, absolute-zero rejection, SI/IEC data sizes, formatting, UX model with fake clipboard, metadata) and `DeveloperToolsTests` (base converter incl. BigInteger/prefix/limits, standard hash vectors, UUID version/variant vectors, privacy/audit reflection checks, ViewModel behavior with fake clipboard).
- `dotnet test` uses a fake clipboard adapter; no real clipboard, network, clock, or sleep-prevention call is made.

## Integration checks

- `--ui-smoke`: Light/Dark WPF resources/layout for all 11 top-level module views and QR, Color, Time, Random, Unit Converter, Developer Tools pages; verifies all six static Utilities navigation templates and 560-DIP Time/Random/Unit/Developer layout without horizontal scrolling — PASS.

## Security and privacy audit

- Full-source grep of `src/` found no `HttpClient`, `WebClient`, `RestClient`, `Download/Upload`, `TcpClient`, `Dns.` or `WebRequest` usage; Unit Converter and Developer Tools introduce no network path.
- `NumberBaseConverter`, `TextHashService` and `UuidInspector` are static pure functions with no instance state and no Save/Persist/Log members (asserted by tests). The Utilities assembly references no `System.Net.Http`, `System.Net.Requests` or logging assembly (asserted by test).
- No `File.*` / `Process.Start` / shell invocation exists anywhere in `WindowsToolbox.Modules.Utilities` production sources; no telemetry.
- Hash inputs/results and UUID/base inputs are session-memory only; oversized text hash (> 10 MiB) is rejected and points users to File Tools.

## Reference accuracy

- Length/mass/area/volume/pressure/energy/power/data conversions use exact decimal definitions (international inch/pound, thermochemical calorie, 1 US gal = 231 in³, SI vs IEC powers of 1000/1024); pressure psi and repeating factors are centralized with source comments.
- Temperature uses dedicated affine formulas with order-of-operations chosen so 0 °C → 32 °F, 100 °C → 212 °F and 0 °C → 273.15 K are exact; Kelvin ≥ 0 enforced (Celsius ≥ −273.15 °C).
- Angle uses a 28-significant-digit decimal π; degree↔radian asserted within 1e-9 of the reference value.
- Hash outputs verified against published standard vectors (empty/`abc` MD5/SHA-1/SHA-256/SHA-512) plus Python hashlib vectors for Chinese/Emoji/Unicode UTF-8 inputs.
- UUID version/variant verified against RFC 4122 known vectors with canonical-string nibble extraction (never .NET Guid byte order).
